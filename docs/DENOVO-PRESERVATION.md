# De novo preservation evidence

The X6/C13 cohort contains 619 retained observations from the frozen
`DeNovoControl.xaml` and `DeNovoControl.xaml.cs`. The frozen inventory and its
previously approved exclusions are unchanged. No product code is changed by this work.

The first batch proposes 182 distinct observations for review. The declaration register
covers 92 rows and the runtime register covers 168, with 78 shared observations. The other
437 observations remained OPEN at that checkpoint. A declaration proves its named property or complete member,
not an interaction. The runtime check proves the control or resolved value it compares,
not a handler, an export or a numerical calculation.

`--prove-denovo-ledger <frozen-source-root> <fresh-output> <date>` verifies the two frozen
source hashes and uses the shared declaration/member comparers. Its current XAML scope is
the De novo module. Its C# scope is the DeNovoControl partial files. The reviewed mapping
from the old partial class to Compatibility, Dialogs and Tables still requires exact complete
member tokens, including every branch and literal occurrence. Changed members stay OPEN.

`--prove-denovo-runtime <frozen-source-root> <frozen-app-folder> <fresh-output> <date>`
loads the actual frozen program alongside 2.0 and hosts both controls off screen. It records
the initial source state, then selects each of the three legacy de novo sources in both themes.
It compares visible named controls,
resolved scalar properties and whole column tooltips. Physical frozen HeaderStyle assignments
identify each tooltip fact; a text search cannot supply a replacement value or close a row.
Missing or unequal values stay OPEN. Binding expressions without a resolved-data fixture and
unnamed style declarations are outside this check.

The reference DLL's assembly version is 1.5.0.0. The native check verifies its informational
version against the full frozen commit, `e9b73064d8ff19b2fde3e3231240b636a64c0a91`, and records
the DLL hash. Both frozen source hashes must also match the inventory. The initial incorrect
assembly-version assertion failed and that execution was not imported.

Each receipt records the actual command, timestamp supplied from `date`, executing commit,
exact per-row comparison and current implementation hashes. The lane output retains the
execution log, comparison JSON, frozen/current source snapshots and the compiled checker,
app and Core assemblies. Runtime rows also hash the participating De novo sources so changes
to a helper invalidate the receipt. Repeat executions produced byte-identical comparison JSON;
dated execution receipts retain their distinct provenance.

paths, exports or handlers. These fixtures make no fresh RAW,

pairs per case must agree byte-for-byte, including ambiguity and quoted/comma-containing IDs.
The source-aware additional CSV fields are outside that legacy-byte comparison.

333 OPEN rows. The 41 compared status-copy observations that differ
