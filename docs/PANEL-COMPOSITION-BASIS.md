# Panel-family headline unit

With a current panel, the report headline and primary composition plots use effective panel-family totals. Candidate UserIDs under the same effective key are deduplicated before the shared-peptide policy by the native effective-panel study. Mean/error bars, pooled subclasses, ring and abundance/diversity use one selected result and threshold partition.

`ReportCompositionBasis` is a read-only reporting view. Multiple source UserIDs require a current stored effective-panel bundle; an absent bundle refuses before an optional source-family search. One-to-one panel mappings reuse the original stored summaries and run denominators, with no regrouping arithmetic. Projects without a panel retain their source-family unit.

Original UserID studies and CSV names/bytes remain in the supplement. New `panel_family_*` exports record the selected headline, run means, run shares, denominators and Others membership. Source-family diagnostic figures keep their filenames and are placed in the supplement; stored world/coverage studies with a different grouping remain explicitly secondary. Per-panel briefs receive the selected partition mapped back to source membership, rather than a second threshold rule.

The automatic findings section uses the same selected native shares, counts, subclasses and threshold partition as the headline. Its study-local IDs resolve through the selected panel map; panel member counts follow effective merge keys. `panel_family_report_findings.csv` records those primary statements. The original `report_findings.csv` remains available with the source UserID findings, so the merge does not rewrite an existing source export.

Fixtures run with `--test-panel-headline [owned-output]` and are registered once in DefaultSuite. They show before/after on a shared-within-key case, inspect actual composition plot inputs, retain old exports, refuse missing studies, exercise one-to-one and no-panel behavior, and execute the native copy-proof harness on a small saved fixture.

The native proof commands are:

* `--inspect-panel-headline-inputs <owned-project-folder> <owned-output>` records panel/application facts from stored project archives without attribution or RAW access.
* `--check-panel-headline <owned-project-copy> <owned-output>` requires a one-to-one mapping and exact equality of all non-label headline cells, including row identities and unavailable values.
* `--check-panel-headline <owned-project-copy> <owned-output> <owned-retained-hit-cache> --counterfactual` records a clearly labelled counterfactual split. It chooses the first eligible panel group in ordinal key order, moves the first half of ordinal protein identifiers to a fresh source UserID, and preserves protein sequences and inherited per-protein panel keys. The grouping is a diagnostic user choice, not an observed biological result or a rule based on signal. All numerical studies are cleared and recomputed by native methods; original quant values are not changed, and old study hashes are never retagged. The retained-hit cache must validate; a miss aborts before any search.

The counterfactual refreshes stored spectrum family memberships, recomputes subclass labels, removes grouping-dependent sensitivity/world results rather than silently reusing them, and writes a separately named project. Source copies remain byte-identical. Before/after CSVs and JSON provenance distinguish identity proofs from counterfactual evidence. Neither mode extracts RAW data or renders figures.
