# Historical composition CSV ledger proof

The SH declaration pass keeps its exact member-token comparer. J12 moved the
historical four-argument `CsvReport.BuildFamilyComposition` body into a formatter
overload; the historical overload forwards with a null formatter. Those thirteen
export observations need executed file evidence, not declaration equality.

After a Release build, run with a timestamp obtained from `date`:

```text
FamilyQuant.Tests.exe --ledger-shell-compare <frozen-source> <fresh-output> <date> <frozen-app>
```

The optional final input keeps the original four-argument command compatible.
It names the pinned 1.5 app folder containing `FamilyQuant.dll`. The producer
checks that assembly's reference commit and the frozen source inventory hashes.
It binds the thirteen observations to their exact frozen physical literals and
containing member; no observation ID exception list is used.

The native frozen and current public four-argument overloads write complete CSVs
for every shared-peptide policy in en-US and pt-BR. Fixtures cover tied ordering,
nonzero shared and unattributed signal, empty families, positive/zero/negative/NaN
denominators, and names/bases containing commas, quotes, line breaks, whitespace,
Unicode and an organism suffix. Each frozen/current file pair must agree byte
for byte, both versions must repeat across cultures, and every recorded literal
must be witnessed. Inputs, thirty native file pairs, hashes, frozen assembly,
frozen source and checker source are retained. These are synthetic writer checks;
they make no extraction or biological accuracy claim.

The thirteen SH rows receive explicit native test receipts. The declaration
comparison remains a nonmatch, with its original reason. Other existing SH/C1
declaration and interaction checks retain their proof routes.

Append `--negative-control` after the frozen app path to corrupt one current
header. The native comparisons and the thirteen fact guards must fail, and no
SH/C1 register is published. Never import a negative packet.

For the desk-owned refresh map, append `{in:referenceApp}` to the existing
`shell-compare` producer's arguments, after `{date}`. The producer still writes
the existing `SH` and `C1` registers; no new register is required.

The six N6a `SuperClusterPreviewWindow.BuildGrid` tooltip rows need no new ruling
or relaxed text rule. The existing reviewed `Paulo-rulings` receipts map that
frozen member to `InstallKeywordHeaders`. Refresh/import those rulings before
running `text-preserved`, or rerun the text producer after their import. A text
pass before the rulings refresh correctly skips the six while the required

## Source receipt portability

Current C# and XAML implementation receipts may survive checkout line-ending
conversion only when the row's proof runs retain the recorded source artifact.
That artifact must pass its original raw SHA256 and have the same source-file
extension. Current and recorded bytes must then be identical after replacing
CRLF with LF on both sides. BOMs, standalone carriage returns, whitespace and
literal contents receive no other transformation. A source receipt without
those recorded bytes needs native re-execution when its raw hash differs.

Frozen sources, assertion logs, images, assemblies and all retained artifacts
still require exact raw hashes. Normalization applies only to the comparison of
current source against an already valid retained source artifact.

Focused controls are available as `--test-ledger-receipt-fixtures`; they cover
mixed endings, a missing source pin, changed source text, tampered retained bytes,
standalone carriage returns and binary refusal. `--test-ledger-import-batch`
checks that the same validation remains atomic during batch import.
