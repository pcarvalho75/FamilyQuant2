# Help and tooltip preservation receipts

The native audit at C13 commit `24edfd3` identifies 435 OPEN help facts and
177 OPEN tooltips. Valid earlier proofs are excluded. N5 implementation mappings
without execution evidence remain eligible. No DROP is proposed.

The first packet compares that complete 612-row cohort. It supports 362 help
facts and 42 tooltip declarations, leaving 73 help facts and 135 tooltips OPEN.
The producer writes three registers with 200, 200 and 212 observations, including
the explicit unsupported cases. Authors propose states for independent review;
they do not accept their own kind reviews.

For a Help fact, the shared member comparer first identifies the exact frozen
literal and its unique containing member. The native program generates General
Help for every reporting mode/shared policy with no PatternLab project and three
recorded denominator fixtures, plus default/custom de novo Help for each source.
It lays out the actual read-only `TextReportWindow` text control and records the
resolved text. The comparison requires the exact case-sensitive frozen text
fragment in that same Help builder's published text; only whitespace is collapsed.
The receipt names the member, original literal, actual fragment and configuration.
It does not claim whole-method token equality or execute a Help-menu handler.

Numeric substrings, another member's copy, unsupported literal syntax and empty
whitespace facts cannot acquire this proof. Decorative lines compare as whole
lines. Changed wording requires a specific preservation check and stays OPEN in
this first packet. The checker's negative controls were red before implementation.

Unchanged tooltip properties use `LedgerDeclarationComparison`: exact named
element, local type and explicit property value within the same logical module.
The curation module includes its extracted quantitation panel; the former Compute
window maps to Quantify and the shared de novo filter view. Missing/unnamed anchors,
markup and changed properties remain OPEN. Declaration receipts do not establish
reachability, handlers or numerical behavior.

The packet retains frozen/current comparisons, the complete Help text corpus,
source/checker snapshots, compiled assemblies and artifact hashes. Two native
runs produced byte-identical `comparisons.json`. Metadata records each real
execution's timestamp, paths and commit separately.
