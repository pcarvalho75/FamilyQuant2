# App and Home native packet

The recovered LK work is retained in `Program.LookAppTokens.cs`,
`Program.LookHomeProbe.cs` and `LOOK-APP-TOKEN-ROLES.json`. It runs the actual
WPF controls. All shown probe windows are off screen, have `ShowActivated=false`
and do not take keyboard focus. No scientific engine is run by these commands.

The Home command checks all five navigation requests together, their project
enablement, and disabled explanations in both themes. It also runs the existing
Home recent-file, last-result and preference checks. A negative control disables
the loaded project's Quantify button and must fail the screen-level check.
The JSON retains actual style properties, text, tooltip values, native template
parts and event counts. The two PNGs are 1366 by 900 at the harness DPI. They do
not establish operating-system scaling or actual keyboard-focus visibility.

The palette command checks six explicit frozen palette roles against named,
constructed Home consumers in both themes. The seventh GoldBrush observation
stays OPEN: a primary-action accent does not by itself prove the old focus and
step-number roles. `LK-app-tokens` is an LK-owned candidate register. Import and
stale-register refresh belong to the gate; this packet does not rewrite another
lane's register or declare a DROP.

The 73 declared OPEN App/Home observations are accounted for in the lane's
`out-look/general-wording/app-home-wording-triage.json`. The removed StepCard key
maps to the current named Fluent actions; the native action check establishes
their event/state behavior. StepCard's former fixed dimensions, StepNumber,
StepTitle, StepBody and the numbered-card wording are intentional presentation
changes, with old/new destinations on `reviews/wording-for-paulo.tsv`. They stay
OPEN unless independently proved or ruled on by Paulo. Unchanged plain text is
left to the shared text checker under the desk's M1 instruction.

installed-product, DPI or final-look acceptance. D23 now runs C14 beside N6;
